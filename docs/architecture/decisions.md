# Architecture decision index

One row per decision, grouped by area. The date is when the decision first appeared in the
repository. Each record links to the document that explains it in full.

| # | Date | Decision | Reason | Alternatives not chosen | Record |
|---|---|---|---|---|---|
| 1 | 13 Oct 2026 | Three Terraform roots (`bootstrap`, `foundation`, `platform`) split by lifetime, each with its own state key | The expensive, disposable resources (NAT gateway, EKS) can be destroyed without touching state, images or CI identity | One root for everything; Terragrunt | [README](../../README.md#infrastructure-terraform), [infra/terraform](../../infra/terraform/README.md) |
| 2 | 13 Oct 2026 | One NAT gateway for both AZs | Lower cost for a development environment; the loss of eu-west-2a outbound access is accepted | One NAT gateway per AZ | [Costs](../infrastructure/costs.md) |
| 3 | 13 Oct 2026 | Worker nodes only in private subnets; IMDSv2 required; public API endpoint limited to configured CIDRs | Nodes are never directly reachable from the internet | Public nodes; a fully private endpoint with a bastion or VPN | [Network security](../infrastructure/network-security.md) |
| 4 | 13 Oct 2026 | EKS Pod Identity, one IAM role per controller and service account | No per-cluster OIDC provider; matches the CNI, EBS CSI and ETL roles | IRSA; node-role permissions shared by all pods | [DNS and certificates](../infrastructure/dns-and-certificates.md#decisions) |
| 5 | 14 Oct 2026 | Every platform-created IAM role carries the `finsight-dev-workload-boundary` permissions boundary | Caps what any created role can do, including roles the CI apply role creates | No boundary, relying on each role's policy alone | [Terraform CI](../infrastructure/terraform-ci.md#workload-permissions-boundary) |
| 6 | 13 Oct 2026 | GitHub OIDC with roles bound to exact environment subjects; no AWS keys in GitHub | No long-lived credentials to leak or rotate | IAM user access keys stored as secrets | [Terraform CI](../infrastructure/terraform-ci.md#roles) |
| 7 | 14 Oct 2026 | Pull requests plan with a read-only role; apply is manual, approval-gated and applies only an age-encrypted saved plan whose digests match the reviewed one | What is applied is exactly what was reviewed; a pull request can never change AWS | Apply on merge; Atlantis or Terraform Cloud | [Terraform CI](../infrastructure/terraform-ci.md#approval-gated-apply-githubworkflowsterraform-applyyml-issue-11) |
| 8 | 15 Oct 2026 | Argo CD app-of-apps with automated sync, `prune` and `selfHeal`, ordered by sync waves | Git is the single source of truth and manual drift is reverted | Flux; `helm upgrade` from CI | [Argo CD](../infrastructure/argocd.md#design) |
| 9 | 15 Oct 2026 | F5 NGINX Ingress Controller behind an internet-facing NLB with IP targets | Meets the NGINX requirement without the retired community `ingress-nginx`; the NLB sends traffic straight to the controller pods | Community `ingress-nginx`; an ALB Ingress | [Ingress](../infrastructure/ingress.md#design) |
| 10 | 15 Oct 2026 | cert-manager with Let's Encrypt DNS-01 through Route 53; staging issuer first, production from 16 Oct 2026 | DNS-01 works before the load balancer exists; staging first limits the risk of production rate limits | HTTP-01; AWS Certificate Manager on the load balancer | [DNS and certificates](../infrastructure/dns-and-certificates.md#decisions) |
| 11 | 15 Oct 2026 | ExternalDNS in `upsert-only` mode with a TXT ownership registry, limited to named records in one zone | It cannot delete records or change records it does not own | `sync` mode; records managed by Terraform | [DNS and certificates](../infrastructure/dns-and-certificates.md#ownership-and-txt-registry-r65) |
| 12 | 15 Oct 2026 | PostgreSQL 17 as a single-replica StatefulSet in the cluster | Lowest cost and fully reproducible; the data is synthetic | Amazon RDS; a PostgreSQL operator | [Argo CD](../infrastructure/argocd.md#in-cluster-database) |
| 13 | 15 Oct 2026 | Database credentials created out of band as a Kubernetes Secret by `scripts/new-cluster-secrets.ps1` and referenced by name | No secret value in Git or in rendered manifests | Sealed Secrets; External Secrets with AWS Secrets Manager | [Argo CD](../infrastructure/argocd.md#bootstrap-during-a-deployment-window) |
| 14 | 15 Oct 2026 | Images built once, scanned by Trivy (fixable HIGH/CRITICAL fail the job), pushed by commit SHA to immutable ECR repositories and deployed by digest through a GitOps pull request | The deployed bytes are the scanned bytes, and every deployment is a reviewed commit | Mutable `latest` tags; CI writing directly to the cluster | [Application pipeline](../infrastructure/app-pipeline.md#jobs) |
| 15 | 15 Oct 2026 | kube-prometheus-stack with Grafana and Prometheus on ClusterIP only, reached by port-forward | No public monitoring endpoints to secure | Amazon Managed Prometheus and Grafana; a public Grafana Ingress | [Monitoring](../infrastructure/monitoring.md#design) |
| 16 | 13 Oct 2026 | ETL: Python transform, Parquet, then load into PostgreSQL; S3 staging and dbt ELT left as planned work | Keeps the deployed data path small; the S3 bucket and ETL role are in place for the next step | dbt from the start | [Day 1 architecture](day1.md#etl--elt-boundary) |
| 17 | 20 Oct 2026 | Separate PostgreSQL roles: an administrator for bootstrap only, a writer for migrations and the ETL, a read-only reader for the API; local and CI first, Kubernetes as a follow-up | The API cannot change data or schema even if compromised; passwords reach the server only as SCRAM verifiers | One owner role for every component (the earlier design) | [Database roles](../infrastructure/database-roles.md) |
